R87 local vendor_boot assembly preparation

This directory creates no device connection, flash operation, or released image.
assemble.py refuses to create any output unless all actual new R87 inputs are
present and agree: successful exact run/head, frozen source/build contracts,
complete artifact lock, all47 compiled KOs, static294 closure against the retained
R84 kernel, and a frozen R87 native helper contract/preparation/binary. The R86
draft helper or R86 module archive cannot pass this gate.

The reviewed layout retains the normal249 module files, normal modules.* metadata,
TFA/brightness/audio/Wi-Fi/CNSS paths and ready/DSP order. The two old synchronous
readonly-owner helper calls are replaced with one /vendor_dlkm/r32/r87-mca-start.
That new helper is the only loader for45 additional coherent source modules at
/vendor_dlkm/r32/r87-mca/<name>.ko. Existing hwid/miev are reused only if their
actual bytes match the newly compiled source pair exactly. Old readonly KOs and
helpers remain inert on disk and are never selected by the new loader/aliases.

Space is explicit, not a silent fallback. The original72MiB RAM vendor_dlkm ext4
has only162 free4KiB blocks. Its copied RAM image is grown to exactly80MiB via
--vendor-payload-bytes=83886080. This is not a physical partition resize: outer
vendor_boot remains100663296 bytes. The new size stays within the unchanged PID1
512MiB payload bound, is4096-aligned, and is checked through the updated pinned
R36_VENDOR_BYTES, held-file hash and loop BLKGETSIZE64 verification. No further
growth is attempted if80MiB is insufficient.

PAYLOAD-GROWTH-REVIEW.json records an actual double-growth experiment: byte
identical results, same single blockgroup,10240 inodes,2210 free blocks, and all
278 old reachable inode/content/xattr records unchanged. Only the filesystem's
internal reserved resize inode7 changes. No final candidate was generated by
that experiment.

The complete assembly repeats growth/install twice, rebuilds PID1 twice with the
recovered exact toolchain, checks every selected294 module from final ext4,
preserves all unrelated reachable inodes/xattrs and the normal metadata, preserves
DTB/bootconfig/CPIO order/metadata and AVB nonhash data, and rebuilds vendor_boot
twice byte identically. Output is under review/ and remains explicitly pending
independent review and hardware validation; it is never described as a released
or hardware-approved flash package.

Native input schema agreed with r87-handover:
  module-set.json: schema1, build_id, kernel, normal_module_count249,
  total_module_count294, baseline_runtime_contract_sha256,
  baseline_vendor_boot{bytes,sha256}, baseline249[{name,path,bytes,sha256}],
  additions45[{name,path,bytes,sha256,load_arguments:''}],
  source_ci{head_sha,run_id,source_contract_sha256,build_contract_sha256},
  abi_review{bytes,sha256}, review_status=FROZEN_REVIEWED_R87_RUNTIME_CANDIDATE,
  activation_allowed=true, runtime_frozen=true.
  PREPARE-REVIEW.json: status=PASS_R87_NATIVE_PREPARATION_NOT_RUNTIME_APPROVAL,
  build_id,module_set{bytes,sha256},helper{bytes,sha256},host_tests_passed=true,
  baseline_image,baseline_contract,source_ci,abi_review,helper_source,
  generated_header,ASan_UBSan_Werror=true,double_build_byte_identical=true,
  activation_allowed=true,runtime_frozen=true. Its directory must contain the
  prepared source/header/exact module-set and identical helper reproduction.
  The exact input module-set.json bytes are installed alongside the new KOs.

Before new CI/native inputs arrive, only the guard tests can be run:
  python3 -B r87-assembly/test_assembly_guards.py

Assembly invocation (replace every placeholder with reviewed actual R87 inputs):
  python3 -B r87-assembly/assemble.py --ci <R87-output> --ci-head <R87-head>
    --ci-run <R87-run> --ci-attempt <R87-attempt> --abi <INACTIVE-FULL-MCA-CLOSURE.json>
    --native-contract <module-set.json> --native-review <PREPARE-REVIEW.json>
    --native-helper <r87-mca-start> --build-id <R87-build-id>
    --vendor-payload-bytes=83886080 --out <fresh-workspace-output>
Add --check-inputs to verify the complete input gate without creating an image.
