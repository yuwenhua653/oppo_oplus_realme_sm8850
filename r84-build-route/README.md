# R84 fast-charge prerequisite compile

R83 device feedback confirms the transient USB-state repair is working and cable insertion no longer returns to the lockscreen. R84 retains that runtime baseline and fixes the physical temperature provider startup/lifetime race while adding a separately enabled, bounded manufacturer identity query to the owned gauge. The query performs a fixed selector write followed by a validated read; it does not alter charging policy or authentication.

This route compiles exactly three ADC/gauge candidates, then the existing declared 47-module full-MCA source closure as a separate inactive validation artifact. The candidate phase completes before the full-stack phase so an unrelated inactive-module compiler failure does not discard already verified candidate outputs. The job result still reports any full-stack failure. Both output sets are compile proof only: installed-kernel ABI, dependency/owner, normal boot, real thermal readings and manufacturer identity remain necessary before runtime selection. No image or charging controls are activated by CI.

The immutable R83 source preparation is pinned by `power-contract.json` SHA256 `aabf43d239c1be0368aefc59bd88bf5ea46c5dfd1bfa193dcdf1adc27eb290a5`, extending its unchanged R79 and earlier input chain. R84 applies only its three frozen overlays afterward: ADC lifecycle, bounded manufacturer query, and error propagation in inactive full-MCA USB power-supply callbacks. The complete inherited postimage map is rechecked after every compile phase with the exact R83 and R84 overlays.

Every one of the 50 requested module outputs is resolved from the actual DDK action graph before the expensive core compile. Candidate and inactive closure inventories are independent. Effective ADC configuration must be the config actually consumed by the ADC compile action, with the panic-on-debug option off. The retained Image, R83 MCA, QTI transport, CNSS and WLAN are authoritative and are not replacements from this run.

`freeze_inputs.py` freezes all route/test files and updates one workflow SHA gate. `build_fastcharge.py --check-inputs` validates the full ancestry. `test_source.py` runs the actual production ADC, gauge and USB callback tests, first on exact offline postimages and again on the actual prepared CI workspace. Neither host tests nor a successful target build are claims of hardware readiness.
